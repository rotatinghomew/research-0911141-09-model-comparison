# 短时复核路径

环境准备和镜像构建在操作前完成。服务的健康入口是 `/health`；服务启动即继续，不固定等待。正常本地启动在数秒内完成。若90秒内没有就绪，应停止操作并保留错误，不把等待算作成功运行。

从首页选择一个数据集，查看各候选的原始预测与成本的图表与明细，点击一条记录，使用“查看原始记录”核对字段。输入会议名称并保存，然后改变所选范围；点击左侧刚保存的记录核对先前材料仍能打开，最后导出当前记录。整段交互通常需要45至75秒，不依赖远程请求。

候选比较应在看到比较结果之前先冻结：勾选候选、设定指标与成本约束，点击“冻结当次候选、指标与证据范围”。冻结记录会说明证据范围是否独立；在 `fixtures/data.json` 上应为探索性，因为 `tuned_tree` 在 `initial` 发布之后加入、`reused` 上改过指标。随后点击“比较候选”，核对：

- 证据等级与原因、每个候选对的共同分折簇与被排除簇；
- 候选汇总使用的共同单元，以及缺折候选的覆盖率；
- 配对差异区间是否跨越零（结论可以为“不足以区分”）；
- 原始误判的 split、repeat、fold、release、subject 归属；
- 业务取舍表里漏判率、时延与覆盖率约束的通过情况。

点击“保存本次比较材料”留存当时的规格与结果。之后若改指标或增加候选再比较，界面会显示“已偏离冻结规格”，保存记录同样带此标记；这不能再当作一次未受影响的确认性结论。若要用独立后续资料做确认，需要导入含新的 release、且该 release 未被改指标事件或在发布后新增候选触及的数据版本，并在看结果前重新冻结。

`fixtures/data.json` 可用于重新导入核对。页面说明的是观测和适用范围；不要为了演示修改数据以制造某种优胜、显著性异常结论。新增加的分析也应从真实可用证据解释结果，不要求出现某个指定方向。
